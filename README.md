# Репозиторий сельскохозяйственных данных MVP

MVP-прототип выпускной квалификационной работы на тему: «Разработка репозитория данных для сельского хозяйства».

Проект демонстрирует не просто файловое хранилище, а репозиторий агроданных: постоянная карточка набора данных хранится отдельно от версий, а изменяемые сущности привязаны к версии. К версии относятся статус, уровень доступа, источник, метаданные, файлы, результаты проверки, структурированные наблюдения и факты экспорта.

## Чем MVP отличается от полной модели v4.1

В полной проектной модели v4.1 предусмотрены отдельные источники версии, история статусов, расширенный аудит, более сложные правила валидации, интеграции с внешними государственными системами и расширенная геообработка. В MVP эти части намеренно упрощены:

- `source_id` хранится прямо в `dataset_versions`, без таблицы `version_sources`;
- статус хранится на версии, без отдельной истории `version_status_history`;
- валидация реализована базовыми проверками CSV/XLSX;
- роли и авторизация сделаны простыми, без OAuth и промышленной RBAC-системы;
- внешние ФГИС/API-интеграции и нейросетевые подсказки не реализуются.

## Запуск

```bash
docker compose up --build
```

После запуска:

- FastAPI Swagger UI: http://localhost:8000/docs
- Streamlit UI: http://localhost:8501
- PostgreSQL: `localhost:5432`

### Если Docker не скачивает образы

Если при сборке появляется ошибка вида `lookup docker-images-prod...cloudflarestorage.com` или `failed to fetch anonymous token`, проблема находится не в коде проекта, а в доступе Docker Desktop к Docker Hub/CDN. Обычно помогает один из вариантов:

1. Включить VPN/прокси именно для Docker Desktop, а не только для браузера.
2. В Docker Desktop открыть `Settings -> Resources -> Proxies` и указать HTTPS proxy, если он используется в сети.
3. В Docker Desktop открыть `Settings -> Docker Engine` и добавить DNS:

```json
{
  "dns": ["8.8.8.8", "1.1.1.1"]
}
```

После изменения настроек перезапустите Docker Desktop и выполните:

```bash
docker compose pull
docker compose up --build
```

Можно также отдельно проверить скачивание базовых образов:

```bash
docker pull python:3.11-slim
docker pull postgres:16-alpine
```

## Как загрузить sample CSV

1. Откройте http://localhost:8501.
2. Выполните вход под demo-пользователем.
3. Создайте набор данных.
4. Создайте версию набора.
5. Откройте раздел «Загрузка файла».
6. Выберите файл `sample_data/sample_observations.csv`.
7. Нажмите «Загрузить и проверить».
8. Если проверка успешна, нажмите «Импортировать наблюдения».

Ожидаемые колонки файла:

```csv
region,agro_object,indicator,unit,period_year,value
```

## Реализованные функции

- `GET /health`;
- `POST /seed`;
- простая авторизация `POST /auth/login`;
- каталог `GET /catalog/datasets` с фильтрами;
- создание `datasets`;
- создание `dataset_versions`;
- upsert метаданных версии;
- загрузка CSV/XLSX в `storage/`;
- расчет размера и SHA-256 checksum;
- базовая проверка файла с записью `validation_results` и `validation_errors`;
- импорт аналитических наблюдений в `observations`;
- карточка набора данных с текущей версией, метаданными, файлами и количеством наблюдений;
- просмотр наблюдений с фильтрами;
- скачивание исходного файла с записью в `data_exports`;
- экспорт observations в CSV с записью в `data_exports`;
- Streamlit-интерфейс на русском языке.
