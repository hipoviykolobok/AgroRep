# Сводка базы данных MVP-прототипа

Модели базы данных реализованы в `backend/app/models.py` с использованием SQLAlchemy. В MVP таблицы создаются при старте backend через `Base.metadata.create_all`. Alembic-миграции в текущей реализации не используются.

## Реализованная логика данных

### Наборы и версии

Основная архитектурная идея MVP сохранена: `datasets` хранит постоянную карточку набора данных, а `dataset_versions` хранит конкретные версии. Метаданные, файлы, результаты проверки, наблюдения и экспортные операции относятся к версии.

В текущей версии MVP реализовано переключение текущей версии. У версии есть признак `is_current`, а endpoint `POST /versions/{version_id}/make-current` назначает выбранную версию текущей для соответствующего набора.

### Файлы и дубли

Таблица `dataset_files` хранит сведения о загруженном файле: имя, путь в `storage/`, формат, размер, checksum, дату загрузки, пользователя и связь с версией.

При загрузке файла вычисляется SHA-256 checksum. Если в пределах той же версии уже есть файл с такой же контрольной суммой, система возвращает предупреждение о дубликате. Повторный файл сохраняется отдельной записью, но в интерфейсе отображается с различимым именем, например `file.csv`, `file (2).csv`.

При повторном импорте файла-дубля наблюдения от предыдущих дублей того же файла заменяются, чтобы не размножать одинаковые строки в `observations`.

### Наблюдения

Таблица `observations` хранит структурированные значения после импорта. Запись наблюдения связывает версию, исходный файл, регион, агрообъект, показатель, единицу измерения, год и значение.

Импорт выполняется только для строк, которые могут быть сопоставлены со справочниками `regions`, `agro_objects`, `indicators` и `measurement_units`. Ошибки сопоставления фиксируются через механизм проверки.

### Проверка

`validation_results` хранит общий результат проверки файла, а `validation_errors` хранит конкретные ошибки. Правила проверки заданы в коде приложения, отдельная таблица `validation_rules` в MVP не реализована.

### Экспорт

`data_exports` фиксирует операции скачивания исходного файла и экспорта наблюдений в CSV. Эта таблица является журналом предоставления данных пользователю, но не заменяет полноценный общий `audit_log`.

### Удаление

Для пользователя с ролью `admin` реализовано удаление набора данных, версии и файла. В текущем MVP удаление физическое. Soft delete, восстановление удаленных данных, журнал причин удаления и полный audit log не реализованы.

## Соотношение с полной моделью v4.1

| Компонент полной модели | Статус в MVP | Пояснение |
|---|---|---|
| `datasets` | Реализовано | Постоянная карточка набора данных |
| `dataset_versions` | Реализовано | Версии набора, статус, доступ, источник и текущая версия |
| `dataset_metadata` | Реализовано | Метаданные версии |
| `dataset_files` | Реализовано | Загруженные файлы версии и checksum |
| `observations` | Реализовано | Структурированные наблюдения |
| `validation_results`, `validation_errors` | Реализовано | Результаты проверки и ошибки |
| `data_exports` | Реализовано | Журнал скачиваний и экспортов |
| `data_sources` | Реализовано | Справочник источников |
| `version_sources` | Не реализовано отдельно | Источник хранится упрощенно в `dataset_versions.source_id` |
| `version_status_history` | Не реализовано | Хранится только текущий статус версии |
| `validation_rules` | Не реализовано как таблица | Правила проверки заданы в коде |
| `audit_log` | Не реализовано | Есть только журнал экспортов `data_exports` |
| `keywords`, `version_keywords` | Частично реализовано | Таблицы есть, UI/API управления нет |
| PostGIS-слой | Не реализован | Регионы представлены справочником |
| Интеграции с ФГИС/API | Не реализованы | Источники представлены справочником |

## Ограничения текущей реализации

- Нет Alembic-миграций.
- Нет JWT/OAuth.
- Нет production-grade RBAC.
- Нет `version_sources`.
- Нет `version_status_history`.
- Нет `validation_rules`.
- Нет общего `audit_log`.
- Нет soft delete.
- Нет PostGIS и пространственной аналитики.
- Нет автоматических интеграций с внешними системами.
- Нет UI/API для управления ключевыми словами.
